| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1 | Возможность подачи заявки на депозит с сайта | Новый клиент видит список депозитов с актуальными ставками, оставляет ФИО и номер телефона |
| F2 | Передача заявки с сайта в систему кол-центра | После подачи заявки менеджер кол-центра связывается с клиентом |
| F3 | Возможность предложения индивидуальных условий менеджером кол-центра | Менеджер анализирует заявку и может предложить особые условия |
| F4| Идентификация нового клиента только в отделении | Требование регулятора — без личной проверки нельзя открыть депозит |
| F5 | Возможность подачи заявки на депозит в интернет-банке | Клиент выбирает депозит, сумму и счёт списания |
| F6 | Отображение персонализированных ставок в интернет-банке | Ставки индивидуальны для клиента |
| F7 | Подтверждение операции открытия депозита по СМС | Используется существующий СМС-шлюз |
| F8 | Обработка заявки менеджером бэк-офиса на этапе MVP | Бэк-офис подтверждает условия депозита в АБС |
| F9 | Отправка СМС после подтверждения ставки и открытия депозита | Клиент должен быть уведомлён на ключевых этапах |
| U   | Удобство использования (Usability) |              |
| U1 | Единая система дизайна для сайта и интернет-банка | Использование принятой в компании дизайн-системы |
| U2 | Минимальное количество шагов для подачи заявки | Удобство и простота пользовательского пути |
| U3 | Понятный и прозрачный интерфейс для клиентов | Особенно важно для новых и менее цифровых пользователей |
| R   | Надёжность (Reliability)           |              |
| R1 | Доступность не ниже 99,9% | Требование бизнеса к стабильности |
| R2 | Отказоустойчивость при сбое одного ЦОД | Использование резервного ЦОД |
| R3 | Отсутствие прямых интеграций интернет-банка с АБС | Перегруженная БД АБС не должна страдать от онлайн-нагрузки |
| P   | Производительность (Performance)   |              |
| P1 | Отклик пользовательских операций в миллисекундах | Бизнес требует быстрый UX |
| P2 | Устранение задержек загрузки справочных данных | Сейчас данные загружаются более 1 секунды |
| P3 | Горизонтальное масштабирование интернет-банка | Для равномерного распределения нагрузки |
| P4 | Вертикальное масштабирование АБС | Ограничение архитектуры АБС |
| S   | Поддерживаемость (Supportability)  |              |
| S1 | Использование существующих технологий банка | MS SQL, Oracle, Java, .NET |
| S2 | Минимизация доработок ядра интернет-банка подрядчика | Желательно реализовать функционал силами команды банка |
| S3 | Возможность расширения решения после MVP | Переход от ручной обработки к полной автоматизации |
| S4 | Подготовка архитектурной и технической документации | Для дальнейшего развития и сопровождения |
| +R  | + Ограничения (Restrictions)       |              |
| +R1 | Шифрование трафика между клиентом и системами | Передаётся чувствительная информация |
| +R2 | Защита данных при передаче между системами | Особенно сайт ↔ кол-центр ↔ интернет-банк |
| +R3 | Использование очередей сообщений при необходимости | Рекомендуется Kafka на перспективу |
| +R4 | Совместимость новых компонентов с текущими платформами | Ограничение существующих технологий |
| +R5 | Ограничения текущей платформы интернет-банка | Текущий монолит несовместим с Kafka |
| +R6 | Ограничение нагрузки на БД АБС | Прямые онлайн-вызовы запрещены |
