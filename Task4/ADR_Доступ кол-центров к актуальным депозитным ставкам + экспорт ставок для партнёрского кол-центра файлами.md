### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

|**№**|**Требование**|
| :-: | :- |
| NFR-01 | Актуальность данных: ставки должны обновляться минимум 1 раз в сутки (желательно чаще при изменениях), файл для партнёра формируется по расписанию. |
| NFR-02 | Производительность: выдача ставок для операторов кол-центра должна быть быстрой (целевой отклик — миллисекунды) за счёт кэша/витрины в Deposit Rates Service. |
| NFR-03 | Надёжность: сбои интеграции с АБС не должны «ронять» работу кол-центра — допускается деградация (показ последней успешно загруженной витрины с отметкой времени). |
| NFR-04 | Ограничение нагрузки на АБС: доступ к АБС только через адаптер, по расписанию/ограниченно; запрет «каждый просмотр ставки = запрос в АБС». |
| NFR-05 | Безопасность: передача файла партнёру должна обеспечивать целостность (подпись/хэш), а канал передачи — согласованный и контролируемый (например, корпоративная почта). |
| NFR-06 | Совместимость: использовать существующие технологии банка (Oracle в АБС, .NET/MS SQL для сервисов, Java в адаптере допустим), без внедрения тяжёлых новых платформ в MVP. |
| NFR-07 | Сопровождаемость: документация формата файла, состава полей, правил актуальности и времени генерации; журналирование генерации и отправки файлов. |

### <a name="_qmphm5d6rvi3"></a>**Решение**
К текущей архитектуре MVP добавляем возможность:
1) Кол-центру банка видеть актуальные ставки
- Кол-центр (CC Backend) получает ставки через Deposit Rates Service ( DRS - Сервис ставок/продуктового каталога депозитов)  по API, а DRS отдаёт их быстро из витрины (кэш/БД).
- АБС не дергаем на каждый просмотр, чтобы не перегружать Oracle.

2) Партнёрскому кол-центру получать ставки файлами
- Добавляем компонент Rate File Publisher (внутри банка), который по расписанию получает витрину ставок из DRS и формирует файл (CSV/XLSX) + добавляет checksum/подпись.
- Передача партнёру — как файл (email/manual transfer), без API/SFTP.

3) Источник ставок

- Для управления ставками уходим от XLS “по почте” к управляемому источнику — ABS Rates Module в АБС (Oracle/PLSQL) с разграничением прав (депозиты/кредиты).
- DRS синхронизирует ставки из АБС через ABS Integration Adapter по расписанию.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
A1. Прямой доступ системы кол-центра к АБС/Oracle

Минус: риск перегрузки АБС, нарушение ограничения “не ходить в АБС напрямую”, рост связанных изменений.

A2. Оставить ставки в XLS и рассылать по почте всем (и банку, и партнёру)

Минус: нет единого источника, проблемы версий, ручные ошибки, невозможно гарантировать актуальность/аудит.

A3. Для партнёра сделать API/SFTP

Не подходит: по условию партнёр не может принимать API-вызовы/SFTP, готов только к файлам.

**Недостатки, ограничения, риски**

1) Устаревание файла у партнёра: партнёр может открыть не самый свежий файл → обязательно добавлять “дата/время актуальности” в файл + регламент отправки.

2) Риски доставки файла: нужно логирование формирования/отправки, подтверждение получения, запасной канал/контакт.

3) Нагрузка на АБС при синхронизации

4) Безопасность/целостность файла со ставками: нужен checksum/подпись и фиксированный список получателей/канал.
